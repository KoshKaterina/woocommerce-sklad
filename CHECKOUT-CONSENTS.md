# Согласия с сайта → одно поле заказа МойСклада

Новый producer сайта сохраняет `_sc_checkout_consent_snapshot` (schema1) в заказе
WooCommerce. Нормализатор принимает только согласованную версию
`checkout-marketing-v1-2026-10-19`, четыре канала (email/SMS/мессенджеры/звонки),
явный выбор yes/no, timezone-aware время и версию документа ПДн.
Исторические `_agree_marketing_email` не расширяются и не экспортируются этим кодом.
При некорректном/отсутствующем снимке поле пропускается; сам заказ идёт прежним путём.

Дополнительное поле **заказа покупателя** «Согласия с сайта», тип `text`:
`327bfdfa-cbd4-11f1-0a80-1c9d00f0e1bf`.
В Config это константа аккаунта; при пустом значении экспорт отключён.
Email передаётся существующим отдельным путём, в строку согласий не включается.

Пример:

`ПДн: да, реклама (email/SMS/мессенджеры/звонки): нет, дата: 2026-10-19T18:00:00+03:00, версия ПДн: policy-123456abcdef, версия рекламы: checkout-marketing-v1-2026-10-19`

Это история выбора в конкретном заказе, а не актуальный статус подписки человека.
`нет` не отзывает старое согласие, повторная доставка не включает рассылку.
Код не меняет контакт CRM, не запускает отправки и не обновляет поля прежних заказов.

Не создавать заново и не выпускать прежнюю схему передачи в сделку.

Живые существующие поля контакта:

- ПДн:578239, версия578241, дата578279;
- реклама:578245, версия578247, дата578277.

Все поля text; рекламные уже используются другими каналами. Предложен отдельный
разбор одной строки МС в эти поля связанного контакта, с проверкой свежести и отказов.
Обработчик реализован и подключён20.10: Sunscrypt/amo_fix_fields, код603b225,
checkout_consent_sync.py; таймер sunscrypt-checkout-consents.timer раз2мин.

сопоставлять CSV целиком с полем «Согласие» нельзя: там нужен прежний формат Да/Нет.
Единое поле МС сохранено. Старые заметки ниже о готовности касаются только первой
части Woo→МС, не готовности нового маршрута МС→контакт.
